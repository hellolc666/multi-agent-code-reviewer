# 设计取舍

1. **动态路由保留确定性下限。** 身份认证、SQL、文件、事务、并发、网络改动触发
   安全关注；普通 Python 文件至少经过 Correctness/Quality。这样能够展示风险与成本
   取舍，同时避免模型误选零个关键 Reviewer。最多五个节点，省略维度写入报告。
   规则模式稳定可复现，hybrid 仅补充合法建议。
2. **独立 Judge 先查锚点再查因果。** 单个 Reviewer 的自证容易接受虚构路径/行号。
   确定性层拒绝假路径与片段；模型层只看到候选及代码/工具证据，要求触发条件、
   反证与低价值风格过滤。uncertain 可观察；Judge 失败不等于通过。
3. **显式有界的上下文工具。** 跨文件缺陷需要查看调用者/被调用者，但开放 Shell、
   测试执行和任意路径读取会把不可信 PR 代码带出边界。本版只提供只读 AST/文本/hunk
   工具，每轮、每调用和字符数有限。没有向量记忆；样例规模与任务均不需跨 PR 语义库。
4. **JSON 人工发布优于额外队列/checkpoint。** 审查与写评论解耦，默认 dry-run。
   先检查 head SHA，再用远端评论 marker 抵御顺序重试；没有 Redis/MQ/Webhook。
   GitHub 没有原子检查并写评论操作，所以并发首次发布仍可能重复。发布 JSON
   应由受信操作者保管，不能将匿名 `publish` 作为服务端接口。
5. **评测质量不能来自 Mock。** 离线实验验证调用链、预算和输出文件，可记录请求
   计数；Mock 的空回答与脚本化演示都不能衡量模型准确率。A 是一个共享适配器的
   general Reviewer，和上游单流程非逐指令等价。真实 A/B/C/D 指标须用同一已配置
   Qwen、人工签核标签、逐条语义匹配及全部失败运行重新计算。

功能和测试范围记录在 STAGE_RESULTS.md；详细发布限制见 HARNESS.md。
